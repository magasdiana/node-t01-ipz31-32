## 1. Мета проєкту

Серверна частина (backend) для обслуговування приватного садка: облік дітей і груп, розклад занять, розрахунок вартості для батьків та прибутку для власника.

Клієнтської частини немає. Це суто сервер із REST API.

## 2. Технічні обмеження 

| № | Вимога |
| T1 | Дотримання принципів **REST** і робочий функціонал: головна вимога |
| T2 | БД реляційна (**SQL**), але **усі дані зберігаються в JSON** |
| T3 | Окремими колонками дозволені тільки **Primary Key** і **Foreign Key** |
| T4 | Решта даних лежить в одній JSON-колонці (`data`) |
| T5 | Пошук по БД не вимагається (індекси й складні запити по JSON не потрібні) |
| T6 | Обов'язково використати **ORM** (обрано Prisma) |
| T7 | Сервер на **Node.js + Express** |

## 3. Ролі користувачів

| Роль | Хто | Права |
| **Admin** | Власник (дід) | Бачить усе, зокрема прибуток. Змінює ціни, зарплати, харчування, призначає пільги |
| **Manager** | Найманий менеджер (ЗП 80 000) | Те саме, що Admin, але менший рівень доступу. Реєструє дітей |
| **Parent** | Батьки | Бачать тільки **свою дитину**: розклад її групи і вартість навчання. Можуть доповнювати дані про дитину. Чужих даних і чужих знижок не бачать |
| **Teacher** | Викладач гуртка | Бачить розклад з **власної** точки зору |

## 4. Предметна область

### 4.1 Діти та батьки
- FR-01. У садок ходять діти віком **2-5 років**.
- FR-02. Про кожну дитину зберігається інформація про **трьох** батьків/опікунів.
- FR-03. Для дитини можна вказати родича-депутата або іншу важливу особу.
- FR-04. Додаткові дані про дитину (наприклад, "не любить гречку") вносять батьки.
- FR-05. Дитину реєструє Admin або Manager.
- FR-06. Одна сім'я може мати кілька дітей у садку (окрема знижка за це не передбачена).

### 4.2 Групи
- FR-07. У групі лише діти **одного віку**.
- FR-08. Максимум **20** дітей у групі. Жорстка межа.
- FR-09. У кожної групи є **власне приміщення**, **вихователь** і **помічник**.
- FR-10. Більше груп означає більше викладачів і приміщень.

### 4.3 Персонал

| Позиція | Зарплата, грн/міс |
| Викладач | 40 000 |
| Менеджер | 80 000 |
| Вихователь, помічник | базова ставка (**уточнити**) |

- FR-11. Після **12-ї** дитини в групі: вихователь **+5 000** і помічник **+3 000** за кожну наступну дитину.
- FR-12. Admin може змінювати зарплати.
- FR-13. Приміщення коштує **50 000 грн/міс**.

### 4.4 Гуртки та викладачі
- FR-14. Гуртки: **музика, англійська, фізкультура, вільна боротьба, шахмати**.
- FR-15. На кожен гурток **три** викладачі.
- FR-16. Викладачів можна брати у **×2 або ×3** більше, але лише за додатної окупності.

### 4.5 Розклад
- FR-17. Діти перебувають у садку **8 годин**, з них **1 година** сну.
- FR-18. Харчування: **3 прийоми по 30 хв**, не підряд.
- FR-19. Дві групи не можуть бути на одному уроці одночасно.
- FR-20. Розклад рівномірний: кожна група потрапляє на всі гуртки.
- FR-21. **Система формує чернетку** розкладу. Admin або викладачі можуть її коригувати.
- FR-22. Батьки бачать розклад групи своєї дитини. Викладач бачить свій розклад.

### 4.6 Вартість і оплата

- FR-23. Навчання коштує **15 000 грн/міс** без харчування.
- FR-24. **Пільги:** три види зі знижкою **10%, 20%, 30%**. Родичам Admin призначає максимальну, знайомим середню.
- FR-25. Харчування оплачується окремо, ціна залежить від віку: **300 грн/день для 2 років, +100 грн за кожен наступний рік**.

| Вік | Харчування, грн/день |
| 2 | 300 |
| 3 | 400 |
| 4 | 500 |
| 5 | 600 |

- FR-26. Оплата **щомісяця** або **за рік наперед**. При оплаті за рік знижка **12%**.
- FR-27. Система автоматично рахує вартість навчання, харчування, знижки й **кінцеву суму до оплати**.
- FR-28. У рахунку є лише дві статті: навчання і харчування.
- FR-29. Зберігається **історія оплат, знижок і змін вартості**.

### 4.7 Фінансова аналітика (для Admin)
- FR-30. Розрахунок **прибутку по кожній групі** і **загального**.
- FR-31. Розрахунок **мінімальної окупної кількості кімнат**.
- FR-32. Система показує, що садок приносить **максимальний прибуток**, і визначає момент, коли збільшення кількості дітей уже не збільшує чистий прибуток.
- FR-33. Прибуток = виручка (оплати з урахуванням знижок) − витрати (приміщення, зарплати, надбавки, харчування).

## 5. Модель даних (принцип)

Кожна таблиця має лише `id`, потрібні зовнішні ключі та `data` (JSON).

| Таблиця | FK | Що в `data` |
| users | | логін, хеш пароля, роль |
| children | group_id, parent_id | ім'я, дата народження, батьки (3), родич-депутат, вподобання, тип пільги |
| groups | room_id | вік, ліміт |
| rooms | | назва, вартість |
| staff | user_id | ПІБ, посада, зарплата |
| subjects | | назва гуртка |
| lessons | group_id, subject_id, staff_id | день, час початку, тривалість |
| payments | child_id | сума, знижки, період (місяць/рік), дата |

Усі зв'язки тільки через FK. Структуру JSON перевіряє сервер (валідація схеми) перед записом.

## 6. REST API (орієнтовно)

| Метод і ресурс | Опис | Хто |
| `POST /auth/login` | вхід | всі |
| `GET/POST /children`, `GET/PATCH/DELETE /children/{id}` | діти | Admin, Manager; Parent свою |
| `GET /children/{id}/invoice` | сума до оплати | Admin, Manager, Parent свою |
| `GET/POST /groups`, `GET/PATCH /groups/{id}` | групи | Admin, Manager |
| `GET/POST /staff`, `PATCH /staff/{id}` | персонал | Admin |
| `GET /staff/{id}/schedule` | розклад викладача | Teacher свій, Admin |
| `GET/POST /subjects` | гуртки | Admin |
| `GET /groups/{id}/lessons`, `PATCH /lessons/{id}` | розклад групи, правка | Admin, Teacher; Parent читає |
| `POST /schedules` | згенерувати чернетку | Admin |
| `GET/POST /payments` | історія оплат | Admin, Manager; Parent свої |
| `GET /reports/profit` | прибуток (`?groupId=`) | Admin |
| `GET /reports/min-rooms` | мінімальна окупна кількість кімнат | Admin |

## 7. Нефункціональні вимоги
- NFR-01. Усі запити й відповіді у форматі JSON.
- NFR-02. Паролі зберігаються лише у вигляді хешу.
- NFR-03. Документація API (Swagger/OpenAPI).
- NFR-04. Розрахунки виконуються сервером, а не клієнтом.
- NFR-05. Кількість бажаючих необмежена, тож система не має жорстко прив'язуватись до певної кількості груп.

## 8. Припущення
- A1. Місяць має 22 робочі дні (для розрахунку харчування).
- A2. Знижка пільги й знижка 12% за рік **сумуються мультиплікативно**.
- A3. Базова зарплата вихователя і помічника рівна зарплаті викладача (40 000).
- A4. Один урок триває 30 хвилин.

## 9. Відкриті питання (потрібне рішення при апруві)

1. Харчування 300 грн рахується **за кожен день відвідування** чи це разова сума в місяць?
2. Знижка за пільгу і 12% за річну оплату **складаються чи множаться**?
3. Скільки **базова зарплата** вихователя і помічника?
4. Фраза "кілька дітей, хіба якщо родичі адміна": це **виняток із правила** чи для родичів адміна діє інша знижка?
5. Скільки занять на день має мати група і яка тривалість одного заняття?
6. Що вважати **окупністю**: покриття витрат за місяць чи повернення вкладень у купівлю приміщення?

## 10. Критерії приймання
- [ ] API відповідає принципам REST
- [ ] У таблицях лише PK, FK і JSON-колонка
- [ ] Права ролей працюють, Parent не бачить чужі дані
- [ ] Група не змішує вік і не перевищує 20 дітей
- [ ] Розклад без накладок викладачів, кожна група має всі гуртки
- [ ] Рахунок враховує пільгу, вік і річну знижку
- [ ] `profit` і `min-rooms` повертають коректні значення
- [ ] Збережена історія оплат
