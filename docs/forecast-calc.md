# Контрольний розрахунок прогнозованого прибутку

## 1. Мета документа

Документ містить контрольний розрахунок прогнозованого прибутку дитячого садка на основі погоджених фінансових правил.

Розрахунок використовується для перевірки правильності роботи `GET /reports/forecast-profit`.

| :--------- | ---------------: | -----------------: |

| 4 роки     |          500 грн |         11 000 грн |

## 5. Контрольний сценарій прогнозу

Для перевірки розрахунку використовується такий сценарій:

| Параметр                 |   Значення |
| :----------------------- | ---------: |
| Кількість груп           |          3 |
| Кількість дітей у групах | 15, 12, 18 |
| Період прогнозу          |   3 місяці |

Для контрольного прикладу приймаються такі профілі дітей:

- Перша група — 15 дітей віком 3 роки.
- Друга група — 12 дітей віком 4 роки.
- Третя група — 18 дітей віком 5 років.

Пільги для дітей:

- Перша група — 10%.
- Друга група — 20%.
- Третя група — 20%.

Пільги застосовуються лише до плати за навчання.

**Примітка:** наведені вік і пільги є вихідними умовами контрольного прикладу. У фактичному запиті `GET /reports/forecast-profit` ці дані окремими параметрами не передаються — система використовує профілі дітей із бази даних.

Вік дитини визначається за `birthDate`, а пільга — за `benefitType`. Якщо для прогнозованої дитини немає відповідного профілю в базі даних, для контрольного розрахунку використовується вік 3 роки та відсутність пільги.

## 8. Розрахунок прибутку

Формула:

`Прибуток = Загальний дохід − Загальні витрати`

1 064 100 − 1 688 600 = **−624 500 грн**.

Отже, прогнозований прибуток за один місяць становить −624 500 грн.

### 8.1. Прогноз на три місяці

| Місяць    |           Дохід |         Витрати |         Прибуток |
| :-------- | --------------: | --------------: | ---------------: |
| 1         |   1 064 100 грн |   1 688 600 грн |     −624 500 грн |
| 2         |   1 064 100 грн |   1 688 600 грн |     −624 500 грн |

## 11. Розрахунок оптимальної кількості груп

У відповіді `GET /reports/forecast-profit` передбачено об'єкт `optimum`, який містить результати пошуку оптимальної кількості груп у межах перевіреного сценарію.

Відповідно до обмеження параметра `groups`, встановленого в `decisions.md`, допустимий діапазон кількості груп становить від 1 до 50. Діапазон пошуку `optimum` повинен відповідати фактичній реалізації.

| Поле           | Опис                                                           |
| :------------- | :------------------------------------------------------------- |
| `maxProfit`    | Максимальний прибуток серед перевірених варіантів              |
| `bestRooms`    | Кількість груп, за якої досягається максимальний прибуток      |
| `bestChildren` | Загальна кількість дітей у найкращому варіанті                |
| `plateauRooms` | Кількість груп у точці, після якої прибуток перестає зростати  |
| `table`        | Таблиця розрахунків для різної кількості груп                  |
| `note`         | Пояснення результату пошуку                                    |

Таблиця `table` містить такі показники:

| Поле       | Опис                     |
| :--------- | :----------------------- |
| `rooms`    | Кількість груп           |
| `children` | Загальна кількість дітей |
| `profit`   | Розрахований прибуток    |

### 11.1. Визначення `plateauRooms`

`plateauRooms` показує кількість груп у варіанті, після якого прибуток перестає збільшуватися.

Потрібно розрізняти дві ситуації:

- Якщо прибуток наступного варіанта дорівнює прибутку поточного варіанта, зростання прибутку припиняється, але сам прибуток не зменшується.
- Якщо прибуток наступного варіанта менший за прибуток поточного варіанта, прибуток починає зменшуватися.

В обох випадках наступний варіант уже не збільшує прибуток. Тому умова виявлення точки плато має відповідати фактичній реалізації пошуку: прибуток наступного варіанта менший або дорівнює прибутку поточного.

Якщо в межах перевіреного діапазону прибуток продовжує зростати, `plateauRooms` дорівнює `null`, а поле `note` містить пояснення: `У межах розрахунку прибуток лише зростає`.

Якщо груп для розрахунку немає, поля `maxProfit`, `bestRooms`, `bestChildren` і `plateauRooms` дорівнюють `null`, таблиця `table` порожня, а `note` містить пояснення: `Немає груп для розрахунку`.

`plateauRooms` не обов'язково дорівнює `bestRooms`: перший показник визначає момент припинення зростання прибутку, а другий — найкращий результат серед перевірених варіантів.
