# Узгоджені рішення

## 1. Розрахунок прогнозованого прибутку

**Питання:** Чи повинна система аналізувати історичні дані з бази даних для розрахунку прогнозованого прибутку?

**Відповідь викладача:** Ні, розрахунок має виконуватися на основі вхідних параметрів у запиті.

**Узгоджене рішення:** Функція `forecast-profit` розраховує прогнозований прибуток для заданого сценарію на основі параметрів запиту (`groups`, `children`, `months`).

Історичні фінансові показники не використовуються. Водночас система отримує з бази даних актуальні дані про дітей, їхній вік і пільги, а також останні налаштування цін, необхідні для розрахунку.

## 2. Значення параметрів за замовчуванням

**Питання:** Які значення повинна використовувати система, якщо параметри прогнозування не передані в запиті?

**Узгоджене рішення:**

- `groups` — поточна кількість груп із бази даних.
- `children` — фактична кількість дітей у кожній поточній групі.
- `months` — 3 місяці.

Якщо `groups` не передано, система використовує поточну кількість груп.

Якщо `children` не передано:

- для поточної кількості груп використовуються фактичні кількості дітей у кожній групі;
- якщо задано іншу кількість груп, загальна кількість наявних дітей рівномірно розподіляється між прогнозованими групами.

Якщо параметри передані в запиті, система використовує передані значення замість відповідних значень за замовчуванням.

Якщо в базі даних немає жодної групи, значення `groups` за замовчуванням дорівнює 0, що не відповідає встановленому мінімуму 1. Тому поведінку системи в такій ситуації потрібно узгодити окремо: чи повертати HTTP 400, чи дозволяти прогнозування за умови явного передавання `groups` у запиті.

## 3. Формат параметра `children`

**Питання:** У якому форматі потрібно передавати кількість дітей для прогнозного розрахунку?

**Узгоджене рішення:** Параметр `children` підтримує два формати:

- Одне ціле невід'ємне число — загальна кількість дітей, яку система рівномірно розподіляє між прогнозованими групами.
- Список чисел через кому — кількість дітей у кожній окремій групі. Наприклад: `children=15,12,18`.

Якщо передано одне число, залишок після рівномірного розподілу додається до перших груп. Наприклад, 40 дітей для 3 груп розподіляються як `[14,13,13]`.

Якщо передано список, кількість значень повинна відповідати параметру `groups`.

Кількість дітей у кожній групі не повинна перевищувати 20.

## 4. Формування прогнозованого розкладу

**Питання:** Чи повинна система автоматично формувати майбутній розклад на основі прогнозованої кількості груп і дітей, чи лише відображати завантаженість та рекомендації?

**Відповідь викладача:** Система формує розклад на основі спрогнозованих груп та інших параметрів, зазначених у першому пункті.

**Узгоджене рішення:** Функція `schedules/forecast` автоматично формує прогнозований розклад на основі прогнозованої кількості груп і дітей та відповідних параметрів.

Для `forecast-profit` і `schedules/forecast` використовується однакова логіка визначення прогнозованої кількості груп і дітей.

Якщо кількість груп у прогнозному сценарії відрізняється від фактичної кількості груп у базі даних, розподіл дітей повинен відповідати загальним правилам, визначеним у розділах 2 і 3 цього документа.

## 5. Обмеження параметрів прогнозування

**Узгоджене рішення:** Для параметрів прогнозування застосовуються такі обмеження:

- `groups` — додатне ціле число від 1 до 50. Якщо параметр не переданий, використовується поточна кількість груп із бази даних.
- `children` — невід'ємне ціле число або список невід'ємних цілих чисел через кому.
- Кількість значень у списку `children` повинна відповідати кількості груп.
- Кількість дітей в окремій групі — від 0 до 20.
- `months` — ціле число від 1 до 12. Значення за замовчуванням — 3.

Якщо передані параметри не відповідають встановленим обмеженням або кількість значень у списку `children` не відповідає `groups`, система повинна повертати помилку HTTP 400.

## 6. Вік і пільги дітей під час прогнозування прибутку

**Узгоджене рішення:** Для розрахунку прогнозованого прибутку система використовує дані профілів наявних дітей із бази даних.

- Вік дитини визначається за датою народження (`birthDate`).
- Пільга визначається за значенням `benefitType` у профілі дитини.
- Якщо дата народження відсутня, використовується стандартний вік 3 роки.
- Якщо інформація про пільгу відсутня, вважається, що дитина не має пільги.

Якщо кількість або розподіл дітей у прогнозному сценарії відрізняється від фактичного, наявні профілі дітей послідовно розподіляються між прогнозованими групами.

Для прогнозованих дітей, яким не відповідає наявний профіль, використовуються стандартний вік 3 роки та відсутність пільги.

**Питання, яке потребує уточнення:** Потрібно визначити порядок вибору наявних профілів дітей із бази даних для послідовного розподілу. Наприклад, за зростанням ID або за іншим критерієм. Цей порядок має бути однаковим для всіх прогнозних розрахунків, щоб результати були відтворюваними.

## 7. Додаткові групи під час прогнозування розкладу

**Узгоджене рішення:** Якщо для прогнозованого розкладу потрібно більше груп, ніж існує в базі даних, додаткові групи формуються на основі параметрів шаблону групи та дітей.

Такі групи створюються лише для прогнозування в пам'яті програми та не зберігаються в базі даних.

**Питання, яке потребує уточнення:** У наявних записах рішень не визначено повний перелік параметрів шаблону додаткової групи. Перед остаточним прийняттям рішення потрібно зафіксувати, які саме параметри копіюються з наявної групи, які дані формуються окремо, а які значення встановлюються за замовчуванням.

До уточнення цих параметрів не можна вважати шаблон додаткової групи повністю визначеним.

Розподіл дітей між додатковими групами повинен відповідати загальним правилам розділів 2 і 3 цього документа. Кількість дітей у кожній групі не повинна перевищувати 20.

## 8. Результат прогнозування розкладу

**Узгоджене рішення:** Результат прогнозування розкладу повинен містити:

- `lessons` — сформовані заняття;
- `unscheduled` — заняття, для яких не вдалося знайти місце в розкладі;
- `conflicts` — виявлені конфлікти;
- `roomsNeeded` — необхідна кількість приміщень;
- `teachersNeeded` — необхідна кількість викладачів.
