# Узгоджені рішення

## 1. Розрахунок прогнозованого прибутку

**Питання:** Чи повинна система аналізувати історичні дані з бази даних для розрахунку прогнозованого прибутку?

**Відповідь викладача:** Ні, розрахунок має виконуватися на основі вхідних параметрів у запиті.

**Узгоджене рішення:** Функція `forecast-profit` розраховує прогнозований прибуток на основі параметрів, переданих у запиті (`groups`, `children`, `months`). Історичні фінансові дані з бази даних для прогнозування не використовуються. Якщо параметри не передані, система застосовує погоджені значення за замовчуванням.

## 2. Значення параметрів за замовчуванням

**Питання:** Які значення повинна використовувати система, якщо параметри прогнозування не передані в запиті?

**Узгоджене рішення:**
- `groups` — поточна кількість груп із бази даних.
- `children` — поточна кількість дітей із бази даних.
- `months` — 3 місяці.

Якщо параметри передані в запиті, система використовує передані значення замість значень за замовчуванням.

## 3. Формат параметра `children`

**Питання:** У якому форматі потрібно передавати кількість дітей для прогнозного розрахунку?

**Узгоджене рішення:** Параметр `children` підтримує два формати:

- Ціле невід'ємне число — загальна кількість дітей, яку система рівномірно розподіляє між прогнозованими групами.
- Список чисел через кому — кількість дітей у кожній окремій групі. Наприклад: `children=15,12,18`.

Якщо передано список, кількість значень повинна відповідати параметру `groups`.

## 4. Формування прогнозованого розкладу

**Питання:** Чи повинна система автоматично формувати майбутній розклад на основі прогнозованої кількості груп і дітей, чи лише відображати завантаженість та рекомендації?

**Відповідь викладача:** Система формує розклад на основі спрогнозованих груп та інших параметрів, зазначених у першому пункті.

**Узгоджене рішення:** Функція `schedules/forecast` автоматично формує прогнозований розклад на основі прогнозованої кількості груп і дітей та відповідних параметрів. Для `forecast-profit` і `schedules/forecast` використовується однакова логіка визначення прогнозованих груп і дітей.

## 5. Обмеження параметрів прогнозування

**Узгоджене рішення:** Для параметрів прогнозування застосовуються такі обмеження:

- `groups` — додатне ціле число, яке не повинно перевищувати встановлений системний ліміт. Якщо параметр не переданий, використовується поточна кількість груп із бази даних.
- `children` — невід'ємне ціле число або список невід'ємних цілих чисел через кому. Кількість значень у списку повинна відповідати кількості груп.
- `months` — ціле число від 1 до 12. Значення за замовчуванням — 3.

Якщо передані параметри не відповідають встановленим обмеженням або кількість значень у списку `children` не відповідає `groups`, система повинна повертати помилку HTTP 400.

## 6. Додаткові групи під час прогнозування розкладу

**Узгоджене рішення:** Якщо для прогнозованого розкладу потрібно більше груп, ніж існує в базі даних, додаткові групи формуються на основі параметрів шаблону групи та дітей.

Такі групи створюються лише для прогнозування в пам'яті програми та не зберігаються в базі даних.

## 7. Результат прогнозування розкладу

**Узгоджене рішення:** Результат прогнозування розкладу повинен містити:
- `lessons` — сформовані заняття;
- `unscheduled` — заняття, для яких не вдалося знайти місце в розкладі;
- `conflicts` — виявлені конфлікти;
- `roomsNeeded` — необхідна кількість приміщень;
- `teachersNeeded` — необхідна кількість викладачів.
