# Test Cases — Kindergarten API

## Загальна інформація

- **Мета:** перевірити готові модулі API для дітей, груп, кімнат, персоналу, гуртків, цін та оплат.
- **Базова URL-адреса:** `http://localhost:3000`
- **Формат запитів:** JSON, заголовок `Content-Type: application/json`.
- **Статуси:** `NOT RUN` — тест ще не виконано; `PASS` — очікуваний результат отримано; `FAIL` — фактичний результат відрізняється від очікуваного; `BLOCKED` — перевірку неможливо виконати через відсутність необхідних даних або функціональності.

## 8. Перевірка єдиного формату помилок

- **Очікуваний результат:** `400 Bad Request`; помилка повертається в єдиному форматі API.

- **Вхідні дані:** без тіла запиту.

## Примітки до виконання

1. Перед тестами створити або знайти необхідні записи: дитину, групу, кімнату, співробітника, гурток.
2. Для тестів із `childId`, `groupId`, `roomId` використовувати ID, які реально існують у поточній базі.
3. Перед тестом на ліміт групи переконатися, що в ній уже є 20 дітей.
4. Для тестів віку враховувати дату виконання тесту: вік визначається за датою народження.
5. Тести, що змінюють або видаляють дані, виконувати в тестовій базі.
6. У разі невідповідності очікуваному результату зафіксувати фактичний статус, тіло відповіді та кроки відтворення, а потім завести Issue.
7. Ендпоінти для уроків, розкладу та звітів у поточному коді не мають реалізованих маршрутів; їх не вважати готовими ендпоінтами в цій колекції.
